# 방탈출 펭크로

현재 빌드: **v6.21**

v6.21은 CGV IMAX 전용 지점 선택과 미오픈 날짜의 영화·상영관·복수 희망시간 사전 설정을 추가하고,
목표 영화 공개 상태에 따라 장시간 대기 감시와 회차 공개 후 고속 좌석 감시를 자동 전환하며,
상영 포맷·희망시간·좌석 우선순위 저장/복원 및 지점·날짜·영화·상영관 변경 시 상태 정리를 개선했습니다.

v6.20은 네이버 오픈 시각 예약을 Chrome 내부 타이머로 직접 제출하도록 개선하고,
실제 예약 응답 지연을 다음 예약 시점 보정에 반영하며 오픈 직전 호출 지연을
최소화해 선점 속도를 향상했습니다.

v6.19는 CGV 미오픈 날짜에 최근 공개 시간표를 대기 기준으로 선택할 수 있게 하고,
선공개 회차에 최근 실제 좌석 배치를 연결하여 목표 날짜 회차 공개 즉시 좌석 감시로
이어지도록 개선했습니다.

v6.18은 CGV 좌석 개방 감지와 동시에 가격 확인·임시선점을 연속 처리하도록 개선하고
선점 성공 전 화면 처리와 중간 대기를 제거했습니다.

v6.17은 CGV 좌석 감시 주기를 단축한 고속 API 교차 감시를 추가하고 선점 경합 시
페이지 갱신 없이 즉시 재감시하도록 개선했습니다.

v6.16은 CGV 실제 좌석 좌표와 통로를 반영한 좌석도 표시를 개선하고 대형 상영관
좌석도 자동 확대와 명당 유형별 연속 좌석 자동 선택을 추가했습니다.

v6.15는 CGV 로그인 완료 직후 좌석 조회 페이지가 닫히는 현상을 방지하고 만료된
로그인 정보 오인 방지 및 페이지 이동 자동 복구를 추가했습니다.

v6.14는 CGV 명당 가이드의 한글 글꼴, 가독성 및 안내 정보 선명도를 개선했습니다.

v6.13은 CGV 다인 예매 시 좌석 우선순위를 같은 열의 연속 좌석으로 제한하도록
개선했습니다.

v6.12는 CGV 좌석도에 상영관별 명당 추천 표시 및 용산아이파크몰 IMAX 전용
좌석 가이드를 추가했습니다.

v6.11은 별도 테스트 브랜치의 Trip.com 엔진이 메인 빌드의 사이트 목록과
사이트 유형에 표시되던 문제를 수정했습니다.

v6.10은 CGV 영화 예매 감시를 추가했습니다. 지점·영화·상영관·회차와
우선 좌석 묶음을 지정하면 미오픈 상태부터 공식 회차 API를 감시하고,
좌석이 열리면 CGV 좌석 모달에서 인원수만큼 선택해 임시선점한 뒤 결제 직전
화면을 유지합니다. 동시 회차 조회는 최대 3개이며 제한 응답과 지연에 따라
자동으로 감속합니다.

v6.04는 앱과 로딩 화면에서 버전 앞의 `v`를 제거하고, 본문 상단에
중복으로 표시되던 프로그램 제목을 없애 상태와 예약 설정에 집중하도록
화면을 정리했습니다.

v6.03은 둠이스케이프 미오픈 날짜 조회 시 새 PC에서도 현재 공개된 날짜를
자동 탐색해 허수아비·옵스큐라를 포함한 지점 전체 테마 시간표를 준비합니다.
같은 요일을 우선 사용하고, 평일과 주말 시간표를 서로 대신 표시하지 않습니다.

v6.02는 둠이스케이프·단편선·지구별·신 제로월드와 공통 실행 경로의
진단 로그를 개선했습니다. 요청 단계, 작업 번호, HTTP 상태, 응답 시간과
재시도 원인을 실행별 회전 로그에 남기되 이름·전화번호·인증 토큰 등은
저장 전에 제거합니다. 서명된 새 EXE를 확인하고 현재 파일에 적용하는 자동
업데이트 UI도 추가했으며, 예약 실행·다중 창과 충돌하면 적용을 미루고 새
버전이 정상 시작하지 못하면 이전 EXE로 복구합니다.

v5.71은 예약용 Chrome에서 로그아웃한 뒤 다른 네이버 계정으로 로그인하면
페이지 초기 상태에 남아 있던 이전 계정을 계속 판정하던 문제를 수정했습니다.
현재 Chrome의 실시간 계정과 쿠키를 다시 읽고, 계정이 바뀌면 이전 CSRF 및
제출 준비값을 폐기한 뒤 새 계정 기준으로 예약을 자동 재개합니다.

v5.70은 네이버가 이미 공개한 목표 날짜의 오픈 시각을 뒤쪽 공개 날짜로
잘못 역산해 조기 제출하던 문제를 수정했습니다. `Duplicated` 응답은 매진과
구분해 중복 제출 없이 예약내역 확인을 안내합니다. 둠이스케이프는 연결을
병렬 예열하고, 서버 장애 중에는 대표 연결 하나만 복구를 확인한 뒤 기존
작업 수 전체를 즉시 재개합니다. 미오픈 날짜는 실제 날짜를 우선 직접
조회하고, 비어 있으면 로컬에 축적된 같은 요일 시간표를 우선 표시합니다.

v5.68은 네이버 이머시브·공연형의 `− / 수량 / +` 티켓 선택을 프로그램
인원과 자동 연동합니다. 슬롯의 최소·최대 수량과 전체·예약 재고를 기준으로
일반 방탈출 1건 예약형과 다매 티켓형을 구분하고, API의 `bookingCount`,
가격별 수량 및 총액과 브라우저 대체 경로의 실제 수량 버튼을 동일하게
맞춥니다. 요청 인원이 잔여 티켓보다 많으면 제출 전에 명확히 중단합니다.

v5.67은 BLACK MUSE처럼 문항 제목에 인원·매수 예시가 있지만 실제
선택지는 `네 확인했습니다` 하나인 추가정보를 수량 선택기로 오판하던 문제를
수정했습니다. 이제 실제 선택지에 숫자 수량이 있을 때만 예약 인원과
대조하고, 안내 확인 선택지는 그대로 자동 선택합니다.

v5.66은 네이버 공연·예매형 상품의 추가정보 문항을 고정 개수로 가정하지
않고 서버 폼 전체를 자동 해석합니다. 선택, 체크박스, 짧은/긴 입력,
생년월일, 성별 및 1인당 반복 문항을 API 직접 제출과 브라우저 대체 경로가
같은 답안으로 처리하며, 공연형 예약 인원을 실제 예매 매수에도 반영합니다.
지도 공연 페이지에 포함된 이스케이프·인코딩 예약 주소 해석도 보강했습니다.

v5.65는 단편선 예약 시작 로그에 선택 날짜의 공식 오픈 예정 시각을
표시합니다. `예약일 - 6일 00:00` 규칙으로 계산만 하며, 기존 즉시 병렬
감시 동작과 제출 경로는 변경하지 않습니다.

v5.64는 단편선 공개 시간표 API를 강남·성수에서 동시성별로 실측해 전용
동시 감시 범위를 1~4개(기본 4개)로 정했습니다. 네 세션의 조회 시작점을
분산하고, 가장 먼저 실제 슬롯을 확인한 세션만 주문 생성 잠금을 통과하게 해
병렬 선점 속도를 유지하면서 동일 실행의 중복 주문을 차단합니다.

v5.63은 단편선(dpsnnn) 전용 엔진을 추가했습니다. 강남·성수 지점과 6개
테마를 자동 등록하며, 공개된 날짜는 실제 슬롯 ID와 예약 가능 여부를 읽고
미오픈 날짜는 최근 동일 요일 시간표를 추정값으로 표시합니다. 오픈 뒤에는
실제 대상 날짜의 슬롯을 고속 감시해 주문을 선점하고 결제 화면까지 이어갑니다.

v5.62는 키이스케이프 미오픈 날짜에 동일 요일 시간표를 우선 표시하고,
오픈 후 대상 날짜의 실제 슬롯 ID를 확인한 경우에만 제출합니다. 빈 값이나
임시 ID 제출을 차단하고 수동 캡차 안전 수명, 서버 시각 경계, 네이버 반복
오픈 일정 재계산도 함께 보강했습니다.

v5.47은 YesCaptcha v5.45 개선과 네이버 API-first 오픈 임계경로 v5.44 개선을 함께 포함한 통합 배포 빌드입니다.

최신 v5.47 빌드에서는 네이버의 상품 공통 `openDateTime`을 선택 날짜의 오픈시각으로 그대로 표시하던 문제를 고쳤습니다. 현재 공개된 마지막 날짜와 그 오픈시각의 관계를 기준으로 선택 날짜별 오픈시각을 계산하며, 아직 네이버 달력에서 닫힌 날짜도 같은 요일의 최신 공개 시간표를 조회해 시간을 미리 선택할 수 있습니다.

v5.45에서는 키이스케이프 핫 스탠바이 동시 제출 시 완료 화면 연결이 끊겨도 예약 API의 성공 응답과 예약번호를 직접 보존하도록 개선했습니다. 같은 실행에서 먼저 성공한 페이지 때문에 나머지 페이지가 받은 `이미 예약 완료` 응답은 오류가 아닌 정상 종료로 구분하며, 제출 후 페이지 연결 종료로 인한 토큰 정리 실패도 캡차 주입 실패로 잘못 표시하지 않습니다. 병렬 설정도 네이버 1개 고정, 키이스케이프 최대 3페이지, 나머지 엔진 최대 50개로 완전히 분리했고 YesCaptcha 설정은 키이스케이프에서만 표시·전달합니다.

v5.44에서는 네이버 API-first 오픈 임계경로를 실사용 기준으로 보강했습니다. 오픈 전후 20초에는 느린 서버시각 재동기화가 제출을 가로막지 않으며, 오픈 직전 로그인·CSRF와 슬롯 ID·가격을 제한시간 안에서 병렬 갱신합니다. 전송 시각은 Python 조회가 아닌 실제 브라우저 GraphQL 왕복 지연으로 계산하고, 네이버 resolver의 상세 거절 사유도 판정에 반영합니다. 브라우저 GraphQL에는 이중 제한시간을 적용했으며 전송 결과가 불명확한 경우에는 중복 예약을 막기 위해 화면 폴백을 자동 실행하지 않습니다. 동일한 서버 거절은 슬롯 상태가 바뀔 때까지 반복 제출하지 않습니다.

v5.43에서는 네이버 일반 EPISODE형 상품을 대상으로 예약 제출도 API 우선 방식으로 전환했습니다. 로그인된 네이버 탭 안에서 계정·CSRF와 현재 상품/슬롯 구조를 미리 검증하고, 서버 시각과 최근 왕복 지연을 기준으로 오픈 순간 `submitBooking` 요청을 페이지 새로고침 없이 전송합니다. 오픈 전 응답만 짧게 제한 재시도하며, 인증·페이로드·네트워크·`RT98` 오류 또는 좌석제·기간제·네이버페이 상품은 기존 화면 제출로 자동 전환합니다. 개발자 테스트 모드에서는 페이로드만 검증하고 실제 예약 요청을 보내지 않습니다.

v5.42에서는 네이버 예약 오픈 시각을 놓치던 문제를 해결했습니다. 네이버 조회 API는 오픈 전에도 잔여석을 알려주지만 오픈되지 않은 날짜의 예약 화면에는 시간표가 아예 렌더링되지 않아, 오픈 직전 제출 시도가 매번 7초짜리 화면 왕복을 헛되게 소모하며 그 시간 동안 감시가 멈췄습니다. 이제 서버 시각 기준 오픈 전에는 화면을 건드리지 않고 대기하다가, 오픈 시각 전용 처리에서 새로고침과 제출을 한 번에 수행합니다. 화면이 준비되지 않았다는 응답 뒤에는 짧은 대기를 두어 같은 실패를 반복하지 않고 API 감시만 계속합니다.

v5.41에서는 키이스케이프 예약 중 사이트의 개발자도구 감지 스크립트가 화면을 검은 차단 화면으로 덮어버리는 문제를 해결했습니다. 감지 무력화를 브라우저 컨텍스트 초기화 스크립트로 올려 캐시된 스크립트와 새 탭·팝업까지 모두 적용되게 했고, F12·Ctrl+U 키 차단 경로도 봉인했습니다. 또한 예약 완료 판정을 완료 페이지 전용 마크업 기준으로 이중화해 실제로는 예약이 접수됐는데 매크로가 실패로 보고 재시도하던 현상을 바로잡았습니다. 함께 프로젝트 폴더를 정리해 조사용 덤프와 외부 참고 리포, 옛 단일 파일 매크로를 제품 경로에서 분리했습니다.

v5.31에서는 실시간 서버 시간 동기화 위젯을 프리미엄 글래스모피즘(Glassmorphism) 네온 카드 디자인 시스템으로 대폭 개편했습니다. 22pt 대형 볼드 디지털 카운터(시:분:초), 14pt 밀리초(.ms) 정밀 표시 및 ⚡ Latency 핑 뱃지를 하나로 결합하여 예약 시각 가독성과 visual WOW 요소를 크게 향상시켰습니다.

v5.30에서는 카탈로그 자동/수동 갱신이 완료되는 즉시, 사용자가 보고 있는 예약 설정 화면의 지점 및 테마 목록 드롭다운에 실시간으로 자동 업데이트(리렌더링)하여 프로그램을 재시동하지 않고도 최신 지점/테마 구조를 바로 사용할 수 있도록 고도화했습니다.

v5.29에서는 둠이스케이프(Doom Escape) 엔진의 실시간 가용 시간대 조회 기능을 추가 및 연동하고, 빌트인 사이트명과 동일한 커스텀 사이트 삭제 시 빌트인 기본 설정이 메모리에서 유실되던 치명적인 현상을 수정했습니다.

v5.28에서는 제로월드 외의 타 방탈출 엔진들(키이스케이프, 지구별방탈출/플레이33, 네이버 예약 등)에 대해서도 실시간 가용 시간대 조회 기능을 대폭 확장했습니다. 또한 플레이33의 hidden 폼 노이즈로 인한 파싱 문제 및 키이스케이프의 모든 시간대 예약가능 오인 상태 판독 버그를 완전하게 해결했습니다.

v5.27에서는 신뢰도를 신규 커스텀 사이트 등록 시에만 보여주는 참고 지표로 변경했습니다. 기존 사이트 갱신은 확정된 엔진을 그대로 사용하며, 신규 사이트는 점수순 후보 중 실제 카탈로그 조회 검증을 통과한 엔진으로 자동 등록합니다.

v5.26에서는 사이트 정보 자동 갱신 중 일시적인 DNS·네트워크 장애가 발생하면 한 번 재시도하고, 계속 실패해도 기존 정상 카탈로그를 유지하도록 개선했습니다.

v5.25에서는 예약 중지·완료 후 GUI 초기화가 반복되어 화면이 깜빡이던 문제와 상태 타이머 중복 가능성을 수정했습니다.

Windows에서 여러 방탈출 예약 페이지를 한 화면에서 감시하고 예약하는 데스크톱 도구입니다.

## 지원 사이트

- 제로월드 신 사이트: 김포본점, 강남점, 홍대점, 다이브 건대점
- 지구별방탈출
- 키이스케이프
- 둠이스케이프
- CGV 영화 예매: 공식 지점 목록 또는 4자리 지점번호 직접 입력
- 네이버 예약 URL로 등록한 커스텀 사이트

구 제로월드 사이트는 기본 지원 목록에서 빠졌지만, 커스텀 사이트가 알려진 엔진에 해당하지 않을 때의 폴백 엔진(`engines/zeroworld_gu_engine.py`)으로 남아 있습니다.

## 설치 및 실행

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
playwright install chromium
py app.py
```

네이버·키이스케이프 자동화는 설치된 Chrome 또는 Edge를 우선 사용하고, 없으면 Playwright Chromium을 사용합니다.

## 개인정보와 보안

- 설정과 예약 기록은 `%LOCALAPPDATA%\Pengucro`에 저장됩니다.
- 이름, 전화번호, 네이버 로그인 쿠키, YesCaptcha API 키는 Windows DPAPI로 현재 Windows 사용자에게 암호화됩니다.
- 이름과 전화번호 저장은 GUI의 `고급 설정`에서 끌 수 있습니다.
- 이전 실행 폴더의 `config.json`, `custom_sites.json`은 호환을 위해 새 저장소로 복사됩니다.
- 검증된 사이트 카탈로그는 `%LOCALAPPDATA%\Pengucro\site_catalog.json`에 원자적으로 저장되고 이전 정상본은 `site_catalog.backup.json`으로 보존됩니다.
- `naver_cookies.json`은 최초 사용 시 암호화 저장소로 이전한 뒤 평문 파일을 제거합니다.
- 과거 소스에 포함됐던 YesCaptcha 키는 노출된 것으로 간주하고 반드시 서비스에서 폐기·재발급해야 합니다.

환경 변수 `PENGUCRO_YESCAPTCHA_API_KEY`를 사용하면 GUI에 저장된 API 키보다 우선합니다.

## GUI 사용 팁

- 날짜 달력과 지원 사이트의 실시간 시간 조회 버튼으로 예약 값을 선택할 수 있습니다.
- CGV 좌석 우선순위는 `A22,A23 | A17,A18`처럼 묶음별로 입력합니다.
- `Ctrl+Enter`: 예약 시작/중지, `Esc`: 실행 중지, `Ctrl+L`: 로그 지우기
- 동시 시도 수, 개인정보 기억, 캡차 키는 `고급 설정`에서 관리합니다.
- `시작 시 사이트 정보 자동 갱신`은 마지막 정상 갱신 후 12시간이 지난 사이트만 조회합니다.
- `현재 사이트 갱신`은 선택한 사이트의 신규 지점·테마와 이름 변경을 즉시 반영합니다. 삭제와 ID 변경은 변경 배지에서 사용자가 확인해야 적용됩니다.
- 커스텀 사이트 등록 시 알려진 예약 엔진의 지문과 카탈로그 조회 결과를 검사하며, 사용자가 추천 엔진을 확인해야 저장됩니다.

## 자동 업데이트 배포

앱은 시작 후 서명된 `latest.json`만 확인하며, 새 릴리스가 있을 때에만 상단
`패치` 버튼 옆에 업데이트 표시를 보여줍니다. 실행 중인 예약이나 같은 EXE의
다른 창이 있으면 적용하지 않으며, 새 EXE가 정상 시작하지 못하면 이전 파일로
자동 복구합니다.

릴리스 EXE를 먼저 공개 업데이트 저장소에 업로드한 다음, 작업 폴더 밖에 둔
Ed25519 개인 키로 매니페스트를 만들고 `latest.json`을 마지막에 업로드합니다.
개인 키를 저장소, EXE 또는 배포 파일에 포함하면 안 됩니다.

```powershell
py tools\create_update_manifest.py `
  --exe dist\방탈출펭크로v6.04_yescaptcha.exe `
  --version 6.04 `
  --release-sequence 604 `
  --download-url https://github.com/terry4025/pengucro-updates/releases/download/v6.04/Pengucro-v6.04.exe `
  --private-key "$env:USERPROFILE\.pengucro-release\update-signing-private.pem" `
  --output latest.json `
  --note "이번 버전에 실제 포함된 변경"
```

현재 공개 바이너리 전용 저장소 `terry4025/pengucro-updates`와 v6.04 기준
릴리스가 준비되어 있습니다. 현재 버전과 공개 버전의 릴리스 순번이 같으면
버튼을 숨기며, 이후 더 높은 순번의 서명된 릴리스가 게시되면 표시합니다.

## 구조

- `ui/`: 화면과 사용자 입력
- `pengucro/`: 예약 요청·결과 모델, 보안 저장소
- `engines/registry.py`: 사이트별 엔진 생성
- `engines/base_engine.py`: 공통 시작·중지·로그·성공 생명주기
- `engines/zeroworld_catalog.py`: 신 제로월드 테마·시간 파서
- `engines/catalog_providers.py`: 엔진 지문 감지와 사이트별 지점·테마 탐색
- `pengucro/catalog.py`: TTL, 변경 비교, 안전 캐시 및 검토 대기 변경 관리
- `engines/*_engine.py`: 사이트별 예약 어댑터
- `reference/keyescape/`: 키이스케이프 예약 페이지 원본 사본. 파싱·차단 우회 로직의 근거 자료입니다.
- `archive/`: 현재 구조로 흡수된 옛 단일 파일 매크로. 실행·빌드에 사용하지 않으며 git에서 추적하지 않습니다.
