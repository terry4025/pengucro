# CGV v6.79 실패 분석과 개선

## 결론

첨부 로그에서 **다음 좌석·시간대 탐색은 실행됐지만, 오래된 좌석 응답에 의존해 첫 시간대에서 89개 조합을 시도하느라 두 번째 시간대 진입이 48.311초 늦어졌다.** 또한 가격 조회 실패와 선점 거절을 모두 ‘선점 경합’으로 처리하고 실제 응답 사유를 기록하지 않아, 89건이 모두 다른 사람에게 빼앗긴 것인지 확인할 수 없다.

미오픈 회차는 2.5초 대기 간격으로 확인했다. 오픈 신호를 받은 뒤 첫 후보 선택까지는 약 414ms, 첫 실패 처리까지는 약 944ms였다. 로그에는 CGV 서버의 실제 오픈 시각과 선점 POST 발송 시각이 없어, 실제 오픈보다 얼마나 늦게 감지했는지 또는 누가 먼저 좌석을 확보했는지는 확정할 수 없다. 표시된 ‘107ms’는 회차 조회의 응답 시간이며 오픈 후 경과 시간이 아니다.

이 패치는 확인한 탐색·오류 처리 결함을 수정한다. 경쟁자보다 항상 먼저 도착하거나 실제 선점에 반드시 성공한다는 보장은 하지 않는다.

## 수정 사항

### 1. 미오픈 감지 간격 단축

- 미공개 날짜: 기존 2.5초 → **1초 대기 간격**.
- 영화별 상영일 목록에 목표 날짜가 공개된 뒤: 기존 1초 → **0.75초**.
- 시간표 변화·선공개 신호 후 집중 감시: 기존 0.5초 유지.
- 조용한 대기 중 1개 요청, 집중 감시 최대 2개 연결, HTTP 403/429 대응은 유지한다.

이는 요청 종료 후 대기 간격이며 응답 지연이 더해진다. 요청 빈도를 무제한 올리는 변경은 아니다. 실제 오픈 전에 신호가 없으면 이전에는 최대 약 2.5초의 대기 구간을 만날 수 있었는데, 그 구간을 줄였다. 개방 후 첫 가격/선점 API의 실제 통신 시간을 줄였다는 실측 결과는 없다.

### 2. 경합 후 최신 좌석표로 재탐색

기존 우선순위 엔진은 첫 좌석 조회 결과를 `candidate_payload`에 보관하고, 다음 조합에서도 그 응답을 새 감시기의 ‘최초 좌석 응답’으로 다시 넣었다. 이미 판매된 좌석과 겹치는 I열 조합을 계속 ‘확보 가능’으로 판단할 수 있었다.

이제 명시적 좌석 경합 후 좌석표를 새로 조회하고, 현재 가능한 완전한 인원수의 좌석 묶음만 다시 고른다. 실패한 정확한 조합은 해당 탐색에서 제외한다. 어느 좌석이 빼앗겼는지 추측해 주변 모든 좌석을 무조건 제외하지 않는다.

좌석 조회에는 2초 제한을 추가했다. 실패하거나 시간 초과되면 오래된 응답으로 다른 조합을 제출하지 않는다. 인증·접근 제한 신호에서는 추가 시간대 API 선점을 멈추고 기존 공식 화면 전환 정책을 따른다.

### 3. 자동 추천 후보가 다음 시간대를 막지 않도록 순환

- 사용자가 수동으로 지정한 좌석 묶음은 같은 시간대에서 입력 순서대로 확인한다.
- 자동 추천은 시간대당 최대 **3개 조합**을 시도한 뒤 다음 희망 시간을 확인한다.
- 모든 희망 시간을 확인하고 돌아오면 이전에 실패한 자동 추천을 반복하지 않고 남은 추천 순서로 이어간다.
- 좌석 가용 상태가 바뀌면 새로 가능해진 상위 후보를 다시 고려한다. 한 바퀴 전체 후보를 소진하면 이후 취소표 감시에서 다시 확인할 수 있다.

이것은 의도적인 정책 변경이다. 첫 시간대의 자동 추천을 수십 개 끝까지 시도하기 전에 두 번째 시간대에도 기회를 준다. 수동 지정 우선순위를 임의로 바꾸지는 않는다. 재현 검증에서는 수동 2개와 자동 3개가 실패한 뒤 다음 시간대의 첫 수동 후보에 도달했다. 서버 응답 시간이 있으므로 이 횟수 제한이 절대 시간 상한을 보장하는 것은 아니다.

### 4. ‘선점 경합’ 오분류와 불명확한 제출 결과 처리

기존 브라우저 감시기는 다음 모두에서 같은 `conflictOrResume()`를 호출했다.

- 가격 조회 API 실패
- 선점 API 실패
- 임시선점 성공 조건 미충족

이제 실제 응답 문구가 이미 선점/판매된 좌석임을 나타낼 때 좌석 경합으로 반환한다. 그 외 가격·선점 거절은 공식 예매 화면 경로로 넘겨 인증·입력·가격 문제를 확인한다. 오류 코드를 추측해서 경쟁 실패로 간주하지 않는다.

선점 요청 후 응답 유실·시간 초과·불완전한 성공 응답은 **결과 불명확**으로 구분하고 자동 추가 선점을 중단한다. 가격 요청 중 통신 실패도 무한히 같은 후보를 재시도하지 않고 화면 경로로 전환한다. 가격 검증과 선점은 기존 순서를 유지하며, 선점 POST를 여러 개 동시에 발송하지 않는다.

실패 로그에는 단계, HTTP 상태, API 상태, 내부 결과 코드/문구, 가격·선점 요청별 소요 시간을 추가했다. 알려진 회원정보와 일반 비밀정보는 기존 마스킹을 적용한다. 앞으로는 가격 조회에서 실패해 실제 선점 POST를 보내지도 못한 경우와, 선점 단계에서 거절된 경우를 구분할 수 있다.

## 검증

**총 449개 오프라인 테스트 통과.** CGV API/엔진/우선순위/미오픈/제한 대응, 네이버 v6.78 수정, 패치노트와 앱 시작·업데이트 연동을 함께 확인했다.

추가 재현 검증:

- 첫 경합 후 새 좌석표에서 판매된 다음 후보를 건너뛰고 유효한 다음 우선순위 선택.
- 큰 자동 추천 후보군에서도 수동 2개+자동 3개 뒤 다음 시간 확인.
- 모든 시간대를 돈 뒤 남은 자동 추천으로 재개.
- 최신 조회가 HTTP 429이면 다른 시간대로 API 선점 확대 금지.
- 실제 배포 코드의 JavaScript를 Node의 가짜 fetch로 실행: 가격 오류는 hold 0회, 선점 응답 유실은 hold 1회 후 정지, 명시적 좌석 경합은 우선순위 제어로 복귀, 정상 선점은 중복 hold 없음.

실제 CGV 서버에 좌석 선점이나 결제를 하지 않았다. Windows GUI·EXE 빌드, 로그인 만료에서 실제 UI 재인증, 실제 개방 순간의 성공률은 미검증이다. 자동 테스트 통과를 실서버 선점 성공 보장으로 해석하면 안 된다.
