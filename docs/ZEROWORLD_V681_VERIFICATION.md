# 제로월드 구조 분석 및 v6.81 통합 검증

검증일: 2026-09-06~07, Windows / Python 3.13.12. 기존 v6.79 릴리스
`e084c07faf81d3e3ea380b9c74905830feaa6a44`에서 제로월드 개선과 CGV v6.80·6.81을 병합했다.
실제 배포 EXE의 검증 결과는 빌드 후 별도 릴리스 결과에 기록한다.

## 사이트 구조와 확인된 문제

- `/core/res/rev.make.sel.php`의 calendar → theme_list/theme_select →
  theme_time_list/theme_time_select가 세션 기반 예약 선택 경로다.
- 미오픈 날짜도 시간표 API 자체는 가짜로 예약 가능한 슬롯처럼 응답할 수 있었다.
  실제 달력의 목표 날짜 공개를 먼저 확인하고 그 날짜의 실시간 슬롯만 제출한다.
- 시간표 선택 화면은 미오픈일 때 가장 최근의 같은 요일부터 최대 4주를 역순 조회한다.
  예상 행은 `estimated=True`, `available=False`, `slot_id=""`이며 과거 상품 ID를 제출하지 않는다.
  실제 조회에서는 2026-09-21의 예상 9개 시간을 2026-09-14에서 가져오는 것을 확인했다.
- 숫자 인증은 같은 세션으로 captcha/session.php 준비 → captcha/image.php 조회 →
  input_captcha 입력이다. 실제 JPEG는 120×60, 표시 크기는 120×50이고 4~5자리다.
- session.php가 정상 검증값 앞에 PHPSESSID 관련 PHP Notice를 붙이는 사이트 오류가 있었다.
  식별한 Notice 형태만 좁게 허용하며 일반 오류·로그인 HTML은 거부한다.
- 주문은 rev.act.php의 act=make, 후속 접수는 rev.make.mutong.php다.
  내부 code·ck_code나 결제 페이지 로드만으로는 완료로 판정하지 않는다.
- 실제 완료 화면에는 예약번호가 빠져 있었다. 이름·전화·이미 받은 예약번호로
  act=rev_view를 한 번 조회해 정상 상태, 목표 일시·테마·인원을 대조한다.
  주문/결제 응답 유실 때 재주문하지 않으며 조회 실패도 성공으로 처리하지 않는다.
  로컬 이력 저장·브라우저 열기 실패가 이미 확인한 성공을 덮지 않는다.

## OCR 검증 방법과 결과

제한된 이미지 인식 후보를 사이트가 제공한 해당 이미지의 검증값과 대조한 결과다.
일반 OCR 모델의 최상위 한 개 출력만의 정확도와는 다르다. 검증값에서 정답을 역산하거나
전체 숫자 조합을 나열하지 않는다. 원본별 검증에는 새로고침·재추출을 사용하지 않았다.

| 표본 | 개선 전/최초 평가 | 최종 같은 원본 재검증 | 용도 |
| --- | --- | --- | --- |
| 최초 100개 | 57 → 91 → 100 | 100/100 | 개발·회귀 표본 |
| 추가 100개 | 95/100 | 100/100 | 최초 독립 평가 후 개선에 사용 |
| 다음 100개 | 코드 동결 상태에서 100/100 | 100/100 | 당시 독립 검증 |
| 최종 추가 500개 | 코드 동결 상태에서 497/500 | 500/500 | 3개 실패 원본 보정 후 회귀 검증 |

최종 총 800개를 통과했다. 500개를 처음부터 모두 맞혔다고 해석하면 안 된다.
검증 통과는 미래 이미지의 100% 성공 보장이 아니다. 서버 생성 규칙·세션·응답 구조가
변하거나 한도 내 인식에 실패하면 잘못된 값을 제출하지 않고 인증 필요로 중단한다.

원인과 개선:

- ddddocr 1.6.1 어댑터의 입력 정규화와 모델 점수 처리에 맞춰 [-1, 1] 입력 및
  숫자 전용 CTC 후보 판독을 사용한다. 일반 문자로 읽힌 뒤 버려지던 숫자 누락을 줄였다.
- 반복 숫자의 CTC blank 처리를 유지하고 두 로컬 모델을 제한된 순서로 사용한다.
- 겹친 글자·기울기·가는 방해선에는 비율 보정, 이진화, 밀집 영역 자르기를 후순위 적용한다.
  후보 폭은 12/32/128로 제한되고 최대 17개 이미지/모델 조합을 사용한다.
- 모델은 시작 시 한 번 예열하며 인식은 비동기 감시 루프 밖에서 수행한다.
  같은 프로그램의 최종 제출 잠금은 유지한다. 검증 실패 이미지로 주문하지 않는다.
- 마지막 500개의 예열 후 로컬 인식 시간: 중앙값 15.2ms, p95 85.7ms, 최대 699.8ms.
  HTTP 조회 시간·모델 최초 로드 시간은 제외한 값이며 실제 예약 선점 속도 보장이 아니다.

재현 도구: `python tools/verify_zeroworld_ocr.py <비공개 원본 폴더> --output <결과.json>`.
EXE의 `--verify-zeroworld-ocr`도 같은 오프라인 검증을 실행한다. 네트워크와 예약을 실행하지 않는다.
원본·검증값은 로컬 scratch에 보존하고 Git에는 넣지 않는다. 결과에는 원본 SHA-256과
성공 여부·시간만 남기고 숫자 정답이나 세션 값을 출력하지 않는다.

## 실예약 및 성공 판정 검증 범위

사용자가 허용한 실제 예약은 정확히 1건만 수행했다. 주문 1회, 후속 접수 1회 후
완료 화면 및 별도 예약내역의 신청 상태·목표 테마/일시·2명을 확인했다.
예약번호는 사용자에게 별도로 전달했으며 개인정보·코드·원문 응답은 이 문서에 포함하지 않는다.
이후 읽기 전용 조회에서 취소/환불 계열 상태를 정상 성공으로 거부하는 것도 확인했다.
추가 예약·취소·유료 결제는 하지 않았다. 경쟁 예약 성공률은 측정하지 않았다.

32작업의 실제 MainWindow → EngineRegistry → BaseEngine.start_reservation 경로를
모의 HTTP로 검증했다. 정상 성공, 주문 응답 유실, 접수 응답 유실 후 읽기 전용 확인 모두
주문은 1회이며 성공/불명 상태와 UI 실행 종료를 확인한다.

## 분석 프로그램 및 CGV 병합

기존 site_inspector를 실제 사이트에 실행해 선택 POST와 인증 준비가 잘못 차단되던 것을 수정했다.
해당 호스트·경로·act·필드만 허용하며 주문·접수·취소는 계속 차단한다. 관련 45개 테스트 통과.
도구 전용 브랜치 커밋: `96eb8a7b641dc7a754df3ba827a607eb22865279`.

CGV는 v6.80 적용 후 v6.81 증분 패치만 적용했다. 누적 패치는 중복 적용하지 않았다.
증분 패치 SHA-256: `8fa0a05ac98f7cea08469519ac022e725fb620b6cbd5059454e2d941660793c4`.
Windows 테스트 파일의 UTF-8 읽기와 기존 DoomEscape·단편선·네이버 수정은 보존했다.
CGV의 시간 변경 기본값은 정확히 일치이며 ±분 허용은 사용자가 명시적으로 선택해야 한다.
CGV 실제 선점·결제·장시간 최소화 감시는 이번 릴리스에서 실행하지 않았다.

통합 소스 검증: 전체 pytest 1,287개 통과, verify_ui.py 9개 통과
(현재 버전 패치노트 버튼·표시 내용 포함). Windows 의존 테스트를 제외하지 않았다.

배포 담당자는 requirements의 ddddocr 1.6.1과 spec에 포함된 두 ONNX 모델을 유지해야 한다.
검증값·개인정보를 포함한 scratch, 기존 예약 로그, 서명 개인 키를 배포물에 넣지 않는다.
