# CGV v6.83: 부분 공개 후보와 선점 전 시간 전환

PR #29 / v6.82에서 재현한 세 가지 경로를 수정한다. 소스 패치이며 Windows EXE 또는 자동 업데이트 배포는 아니다.

## 변경

1. **부분 공개 후보 유지**: 저장된 영화 ID가 있는 상태에서 11:00 회차의 영화 ID가 비어 있고 14:30 회차의 ID가 먼저 공개되면, 이전에는 11:00 후보가 사라졌다. 영화 ID가 다른 행은 계속 거절하며, ID가 없는 행은 정확한 제목·상영 형식·회차 식별값 검증 후 시간 우선순위에 함께 반영한다. 검증된 저장 ID만 가격 요청에 보완한다. 원본 서버 응답과 희망 시간 허용 범위는 바꾸지 않는다.
2. **좌석 판정 일치와 후보 대기 제한**: 상태값 공백, 빈 판매 허용값, 잘못된 좌석 번호·식별값, 중복 좌석의 처리 기준을 Python과 브라우저에서 맞춘다. 빠른 시간 순환은 후보 탐색 시작 기준 약 3초, 수동 우선은 개별 선점 감시 진입 기준 약 8초에 선점 미발송 상태의 대기를 종료하고 다음 시간을 확인한다. 응답은 계속 오지만 선택 좌석이 없거나 가격 응답이 지연되는 경우에도 내부 감시가 시간 전환을 막지 않는다.
3. **좌석 조회 후 회차 재검증**: 좌석 GET 대기 중 갱신된 시간표를 다시 검사한다. 삭제·판매 제한·희망 시간 이탈·영화 변경을 확인하면 해당 후보의 가격/선점을 시작하지 않고 다음 회차로 간다. 감시 중에도 최신 후보 유효성을 확인한다. 재검증 자체는 이미 수집한 시간표를 사용하며 HTTP 조회를 추가하지 않는다.

## 전환과 선점 보호

- Chrome에서 실행 ID·성공 응답·선점 발송 여부를 한 번에 확인한 뒤 중단 여부를 결정한다.
- 가격 대기를 중단한 후 늦게 가격 응답이 와도 선점 POST를 보내지 않는다.
- 이미 선점을 보냈다면 시간 예산이나 회차 변경을 이유로 취소하지 않고 기존 결과 확인을 계속한다. 결과가 불명확하면 기존 성공 응답 복구/정지 정책을 따른다.
- 약 3초/8초는 정상적인 브라우저 연결 하에서의 점검 기준이다. 개별 CDP 호출 정지나 이미 발송한 선점 결과 대기를 포함한 절대 시간 상한이 아니다.
- 선점 감시와 관계없는 단일 공개 회차의 취소표 대기는 기존 동작을 유지한다.

## 검증

CGV·네이버·패치노트·업데이트 부트스트랩 테스트 695개 통과, 기존 Windows 개인 키패드 이미지·보안 저장소 의존 2개 제외. 이번 버전 회귀 테스트 29개를 포함한다.

- 최종 등록 엔진에서 혼합된 부분 공개 응답의 11:00 → 14:30 순서 보존.
- 가상 시간에서 정상 응답 반복/가격 대기 모두 빠른 모드 약 3초, 수동 우선 약 8초에 다음 회차 진입.
- 실제 배포 JavaScript를 Node의 모의 fetch로 실행해 공백·판매 상태·중복 좌석 판정을 확인.
- 실제 JavaScript의 원자적 중단 검사: 가격 중단 후 선점 0회, 이미 선점 발송 시 선점 1회 및 성공 응답 보존.
- 좌석 조회 중 첫 회차 삭제/제한/시간/영화 변경 시 두 번째 회차만 선점 감시 시작.

이는 오프라인 재현 결과다. 첨부된 과거 로그의 실패 원인이 이 세 가지였다고 확정하지 않는다. 실제 서버가 공백 상태값을 보냈다는 증거도 없다. Windows GUI·패치노트 버튼·최소화 장시간 실행·실제 CGV 선점 및 결제는 미검증이다. 성공률을 보장하지 않는다.

## 적용

버전 6.83 / release sequence 6830001. main 기준 `1b19ca41fb8935eb43ce3f20e7d96343e18ebcd2`에서 적용하는 누적 패치와 PR #29 / v6.82에서 적용하는 추가 패치를 제공한다. 두 파일 중 현재 소스에 맞는 하나만 적용한다. 누적 패치는 앞선 네이버/CGV 변경을 포함하며 main의 단편선 변경을 보존한다.

```powershell
git switch -c fix/cgv-v683
git am --3way C:\path\pengucro-v6.83-from-v6.82.patch
```

main/v6.77이라면 파일명을 `pengucro-v6.83-cumulative.patch`로 바꾼다. 추가 변경이 있는 작업 트리는 먼저 보관하고 충돌을 검토한다. Windows 빌드는 커밋된 깨끗한 소스에서 `AGENTS.md`를 따르며, 자동 업데이트 배포는 별도로 `docs/AUTO_UPDATE_RELEASE.md`를 따른다.
