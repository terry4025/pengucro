# CGV v6.80: 감시 주기와 좌석·시간대 전환 개선

v6.79의 최신 좌석 재조회와 자동 추천 3회 제한에 더해, 남아 있던 전환 지연과 후보 반복을 수정한다. 이전 네이버 v6.78·CGV v6.79 변경을 포함하고 main의 단편선 v6.77 변경을 보존한다. 제로월드 코드는 변경하지 않는다.

## 적용된 동작

| 항목 | v6.80 동작 |
| --- | --- |
| 불필요한 현재 시간대 조회 | 자동 추천 한도 또는 빠른 순환 시간 한도에 도달하면 다음 시간대로 넘어가기 전에 현재 시간대 좌석을 다시 조회하지 않는다. 남은 수동 우선순위는 고려한다. |
| 실패 후보 기억 | 자동 후보의 실패 이력을 회차·좌석 묶음별로 유지한다. 무관한 좌석의 판매는 이력을 초기화하지 않는다. 해당 묶음이 불가→가능으로 바뀌거나 30초가 지나면 다시 검토한다. |
| 오픈 감시 | 응답 완료 후 1초를 추가 대기하던 방식에서, 조회 시작 시각을 기준으로 남은 대기만 사용한다. 1초/0.75초/0.5초 상태별 목표 주기를 유지한다. 느린 응답 뒤에는 최소 50ms를 쉬고 지나간 주기를 몰아서 실행하지 않는다. 오류와 403/429 대기는 별도 기존 정책을 유지한다. |
| 자동 추천 계산 | 상영관·인원·추천 모드·좌석 배치별 순위만 최대 8개 캐시한다. 잔여 좌석은 매번 최신 응답으로 확인한다. 기존 선호 모드의 후보가 소진된 경우에만 best 순위를 계산한다. |
| 시간대 순환 설정 | CGV 선택창에 `수동 좌석 우선`과 `빠른 시간 순환 · 약 3초`를 추가한다. 기존 설정은 수동 우선으로 유지한다. 빠른 모드는 실패한 수동 후보도 기억하고 다음 시간대를 본 뒤 남은 후보를 이어간다. |
| 확인 응답 복구 | Chrome에는 성공 응답이 있지만 Python이 설치/결과 응답을 잃은 경우, 동일 실행 ID에 속한 성공 응답을 읽어서 결제 연결로 복귀한다. 확인할 수 없는 요청은 다시 제출하지 않는다. |

빠른 순환의 **3초는 다음 시도에 진입할지 판단하는 기준**이다. 이미 진행 중인 가격/선점 요청을 3초에 강제 취소하지 않으며, 그 응답 시간이 추가될 수 있다. 시간대별 최소 한 후보 시도 후 순환 여부를 판단한다. 자동 추천은 두 모드 모두 시간대당 3회 제한을 유지한다. 모든 수동 우선순위를 먼저 소진하고 싶은 경우 기본 `수동 좌석 우선`을 사용한다.

실패 이력은 좌석을 영구 제외하지 않는다. 본인 선점 결과가 불확실한 경우에는 이 30초 재시도 규칙을 적용하지 않고 전체 자동 선점을 멈춘다.

## 복구의 범위와 남은 제한

복구는 서버가 성공으로 응답한 동일 요청에 한정한다. 새 선점마다 무작위 실행 ID를 부여하고, 브라우저 메모리의 15초 이내 성공 응답을 회차 식별값·좌석 묶음·가격 성공·선점 성공 코드·임시 예매번호와 대조한다. 브라우저 상태의 읽기 재시도는 1초 예산으로 수행하며, 새 HTTP 선점이나 결제 요청을 복구 목적으로 발송하지 않는다. 개별 CDP 호출 자체의 정지는 브라우저 연결의 제한을 따른다.

**서버 응답 자체가 유실되어 성공 증거가 없는 경우의 예매내역 자동 조회는 구현하지 않았다.** 저장소에 검증된 CGV 본인 임시선점 조회 계약이 없고, 공개 검색에서도 해당 계약을 확인하지 못했다. 일반 잔여 좌석의 판매 상태만으로 본인 선점으로 판정하거나 추측한 API를 호출하지 않는다. 이 경우 추가 선점 없이 정지하고 열린 화면/예매내역 확인을 안내한다. 따라서 여섯 번째 제안의 서버 내역 대조까지 모두 완료됐다고 볼 수는 없다.

실제 예매내역 확인 응답의 익명화된 구조를 확보하면 회차·좌석·본인 식별·유효기간을 함께 검증하는 별도 복구 경로를 추가할 수 있다.

## 속도 로그

- 마지막 미오픈 조회 시작부터 첫 회차 확인까지의 구간, 첫 회차 조회·처리 시간.
- 회차 감지→후보 확정, 좌석 조회·선택, 직전 경합→다음 후보 확정.
- 회차 감지→감시 설치 요청, 브라우저 설치 왕복 시간.
- 브라우저 내 좌석 확인→후보, 후보→가격 발송, 가격 왕복, 가격 완료→선점 발송, 선점 왕복.
- 가격에서 실패해 선점이 발송되지 않은 경우는 선점 시간 `미확인`으로 표시한다.

Python은 monotonic, Chrome은 performance 시계로 각 구간을 기록한다. 서로 다른 시계의 절대값을 직접 빼지 않는다. 서버 실제 개방/수신 시각이나 네트워크 편도 시간을 측정한 것으로 표시하지 않는다. 추가 후보 진단 로그는 선점 호출 뒤에 출력해 제출 경로의 로그 부하를 줄인다.

## 오프라인 계산 비교

같은 Linux 환경에서 v6.79 함수와 새 함수를 비교했다. 가상 800석, 4명, 편안형 추천, 각 20회 중앙값이다. 같은 후보가 선택되는지도 확인했다.

| 상태 | v6.79 | v6.80 최초 계산 | v6.80 캐시 재사용 |
| --- | ---: | ---: | ---: |
| 전체 예약 가능 | 1.224ms | 1.333ms | 0.463ms |
| I/J열 중앙 판매 후 | 22.523ms | 1.393ms | 0.503ms |

최초의 전체 예약 가능 사례는 약 0.1ms 느렸고, 판매가 진행된 뒤의 반복 탐색 비용은 크게 줄었다. 이는 CPU 계산 비교이며 서버 RTT, 오픈 감지 실제 지연, 선점 성공률 시험이 아니다.

## 검증

CGV·네이버·패치노트·업데이트 부트스트랩 오프라인 테스트 **596개 통과**, 환경 의존 테스트 2개 제외. 추가한 v6.80 테스트 20개에 다음을 포함한다.

- 자동 3회 실패 후 재조회가 2회만 발생하며 다음 시간대로 진입.
- 다른 좌석 판매 후에도 실패한 자동 추천 3개를 반복하지 않음.
- 해당 좌석의 재개방·30초 경과 시 재검토.
- 수동 우선 모드의 기존 순서 보존, 빠른 모드의 시간대 전환·남은 수동 후보 재개.
- 최신 가용 상태 반영 및 통로 변경 시 캐시 무효화.
- 응답 300ms인 1초 감시에서 남은 700ms 대기, 지연 응답 뒤 따라잡기 폭주 없음.
- 잘못된 회차·좌석·거절 코드·예매번호 누락 응답으로 복구하지 않음.
- 실제 배포 JavaScript를 가짜 fetch로 실행: 성공 응답 보존, 오래된 실행 ID·15초 경과 응답 거부, 선점 POST 1회 유지.
- 설치 응답 유실 후 확인된 결과로 결제 연결, 복구 불가 시 추가 감시/선점 금지.
- 순환 설정이 폼→예약 요청으로 전달되고 버전·릴리스 순서·실행 파일 이름이 일치.

전체 CGV 실행에서 발견한 아래 2개 실패는 수정 전 v6.79 별도 체크아웃에서도 동일하게 재현했다. 이번 패치에서 해당 기능의 구현/테스트를 우회하거나 수정하지 않았다.

- `test_cgv_engine_enter_naver_pay_password_success`: 개인 Windows 경로의 실제 키패드 이미지가 없어 녹색 빈 이미지로 대체되며 숫자 인식 실패.
- `test_cgv_npay_password_persistence_and_reservation_data`: 현재 Linux 환경에서 Windows 보안 저장소 왕복 실패.

v6.77로 고정돼 있던 별도 릴리스 검증은 v6.77 변경 이력 보존 검증으로 명확히 이름을 바꿨다. 새 v6.80 버전·시퀀스·EXE 이름 계약은 새 테스트에서 검증한다.

Windows GUI의 새 선택 메뉴/패치노트 버튼, Windows EXE 빌드, 실제 CGV 선점·결제는 미검증이다. 소스 PR은 draft로 제공한다. 경쟁 상황에서 선점 성공을 보장하지 않는다.

## 적용

버전 `6.80`, release sequence `6800001`. EXE 이름 `방탈출펭크로6.80_yescaptcha`.

- main v6.77 기준 SHA: `1b19ca41fb8935eb43ce3f20e7d96343e18ebcd2`.
- v6.79 검증 소스: `f8032f91daee15976a87c9fc60baac8767d9f49b` (기존 PR #26과 같은 트리).
- `pengucro-v6.80-cumulative.patch`: 위 main에 네이버 v6.78, CGV v6.79와 이번 v6.80을 적용하는 누적 메일 패치.
- `pengucro-v6.80-from-v6.79.patch`: v6.79에 이번 변경만 적용하는 메일 패치.

두 파일 중 현재 소스에 맞는 **하나만** 사용한다. PR 통합과 같은 패치의 수동 적용을 중복 실행하지 않는다.

```powershell
git switch -c fix/cgv-v680
git am --3way C:\path\pengucro-v6.80-cumulative.patch
```

빠른 시간대 전환이 목적이면 CGV 선택창에서 `빠른 시간 순환 · 약 3초`를 선택하고 확인하여 저장한다. 실제 EXE 빌드/배포는 `AGENTS.md`와 `docs/AUTO_UPDATE_RELEASE.md`를 따라 커밋된 깨끗한 소스에서 진행한다.
