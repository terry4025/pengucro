# CGV·제로월드 감시 안정성 개선 / 구형 엔진 제거

작성일: 2026-09-07. 기준 커밋: `b19a14d41176977a82b6c6dc6e8fa48e40934f84` (v6.84).
작업 브랜치: `codex/cgv-zeroworld-reliability`.

이 문서는 **v6.85 (release sequence 6850001) 릴리스 대상 소스 변경** 검증이다. 사용자의 별도 배포 요청에 따라 버전·실행 파일명·패치노트를 동기화했다. 기존 실행 프로그램과 다른 작업 폴더의 미커밋 변경은 건드리지 않았다. 아래 검증은 소스 단계 결과이며, 실행 파일과 공개 자동 업데이트 검증 결과는 배포 결과에 별도로 기록한다.

## 제로월드 신형·신비월드

문제는 미오픈 달력 조회에서 받은 429/5xx가 공통 요청 제어에 전달되지 않던 것이다. 또 반복 루프 입구에서만 허가를 기다려 준비·날짜·슬롯 조회가 연속으로 대기 지시를 건너뛸 수 있었다.

- 달력 조회도 정상/오류 응답을 공통 scheduler에 반영한다.
- 준비·달력·슬롯·인증 조회와 최종 예약 발송의 요청 경계에서 허가 및 중지를 확인한다. 기존 바깥 반복/예열 입구의 중복 대기는 제거했다.
- 테마 목록 준비가 실패하면 다음 테마 선택 요청을 즉시 보내지 않는다.
- Shin/Sinbiworld만 `Retry-After`의 전체 유효 대기시간을 유지한다. 60초를 30초로 줄이지 않는다. HTTP-date도 처리한다. NaN/Infinity/잘못된 값은 무한 대기 대신 기존 지수형 오류 대기로 처리한다.
- 대기는 비동기 sleep으로 이루어지고, 중지 신호를 최대 100ms 단위로 확인한다. OS 스케줄링 지연까지 절대 종료시간을 보장하는 의미는 아니다.
- 다른 작업의 늦은 429도 이미 대기 중인 작업에 반영된다. 뒤늦은 정상 응답 하나로 서버 대기 지시를 취소하지 않는다.
- 최종 허가대기 동안 인증값이 기존 60초 재사용 기준을 넘기면 예약 POST 전에 최대 한 번 다시 준비한다. 다시 오래되면 요청을 보내지 않고 종료한다. OCR 판독 알고리즘은 변경하지 않았다.
- 주문/결제 응답이 불명확한 경우 자동 재전송하지 않는 기존 보호는 유지한다. 429라고 해서 불명확한 최종 주문을 다시 보내도록 바꾸지 않았다.

병렬 슬라이더의 1~32 범위는 유지한다. 다른 엔진에 영향을 주지 않도록 공통 scheduler의 기존 기본 상한(30초)은 유지하고 이 두 사이트 엔진만 전체 대기 정책을 선택한다. 지구별의 긴 Retry-After 정책 변경은 이번 범위가 아니다.

## CGV

- 실제 등록되는 최종 Watchdog 실행 경로가 회원 인증 검사 helper를 호출하도록 연결했다. 부모 클래스만 고쳐 최종 실행에서 빠지는 문제를 방지한다.
- 시간표가 HTTP 200이어도 회원 인증이 만료됐으면 기존 공식 로그인·세션 복구 경로를 거친다. 기존 로그인 도우미를 재사용하며 OCR 구현은 수정하지 않았다.
- 회원 확인은 PC 기준 60초 시작 간격의 단일 비동기 요청이다. 상태는 5초 간격으로 읽는다. 매 좌석 선점마다 추가 인증 HTTP를 요청하지 않는다.
- 멈춘 probe는 호스트 경과 시간 기준으로 취소한다. 5초는 판정 기준이며 정상 상태에서 5초 간격 점검에 따라 보통 5~10초에 취소된다. CDP 자체 정지·OS 절전에 대한 절대 상한은 아니다.
- 90초 이상 갱신되지 않은 인증 근거로 새 회차 탐색·선점에 진입하지 않는다. 만료와 단순 네트워크 오류는 구분한다.
- 브라우저와 PC의 서로 다른 절대 시각을 빼지 않고 각각의 경과 시간을 사용한다. 오래된 완료 응답을 뒤늦게 수집해도 새 인증 근거로 취급하지 않는다.
- 긴 호스트 공백 뒤의 probe 폐기/재설치, 페이지 교체, 정상 중지, 취소된 요청의 늦은 응답, 복구 실패 후 대기를 검증했다.
- 회차/좌석 HTTP 주기, 희망 시간 매칭, 선점 응답 보존과 중복방지는 변경하지 않았다.

## 제로월드 구형 제거

삭제 파일:

- `engines/zeroworld_gu_engine.py`
- `tests/test_zeroworld_gu_engine.py`

구형 catalog provider, PyInstaller hidden import, 테스트 의존성, UI의 지원 엔진 분류를 함께 제거했다. 기존 저장 설정의 구형 ID는 지원 종료 안내용으로만 남긴다. 미확인 사이트나 구형 설정을 신형/다른 엔진으로 자동 실행하지 않는다. 현재 제로월드·신비월드·지구별은 유지한다.

사용자 설정·예약 기록은 삭제하지 않았다. 제거한 코드·테스트는 기준 Git 커밋에 남아 있어 복구 가능하다.

## 검증

- 최종 통합: `python -B -X utf8 -m pytest tests -q -p no:cacheprovider` → **1,677개 통과**, 22.06초.
- UI: `python verify_ui.py` → **9개 통과**. 격리 임시 데이터 폴더 사용.
- CGV 관련 전체 461개 통과. 최종 EngineRegistry 클래스의 가상 18시간 감시/인증 만료, 브라우저 JavaScript의 가짜 fetch·취소·늦은 응답 포함.
- 제로월드·scheduler·기존 안전성 관련 88개 통과. 32개 허가 대기 작업의 중지, 429→대기→실제 목표 공개→모의 주문 한 번, 60초/HTTP-date 지시, 인증 재사용 기준 만료 포함.
- `git diff --check` 정상. 위 부분 테스트 수는 통합 수와 중복되므로 합산하지 않는다.

실사이트 부하 시험, 실제 계정 로그인 완료, 예약·결제, 배포 EXE 검증은 수행하지 않았다. 429 자체가 다시 발생하지 않거나 경쟁 예약에 항상 성공한다는 보장은 아니다.

추가 검토 사항: 기존 제로월드의 **이미 주문 승인된 뒤 결제 단계**에는 별도의 중지 처리 보강 여지가 있다. 이번 변경은 감시·준비·최종 예약 발송 전 대기 경계에 한정하며, 승인 후 결제 흐름을 재설계하지 않았다.

배포는 정확한 소스를 먼저 커밋한 뒤 해당 커밋에서 빌드하고 실행 파일·업데이트를 검증한다. 이후 사용자가 추가 승인한 키이스케이프 타이밍 보정 및 선택형 취소표 감시는 `docs/KEYESCAPE_V685_RELIABILITY.md`에 별도로 기록한다. 위 테스트 수는 키이스케이프 추가 이전의 검증 결과이며 최종 통합 결과는 릴리스 검증에 기록한다.
