# 키이스케이프 v6.85 타이밍 및 취소표 대기

기준: v6.84 `b19a14d41176977a82b6c6dc6e8fa48e40934f84`. 2026-09-07 추가 개선 승인에 따라 CGV·제로월드 개선과 함께 v6.85 릴리스에 포함한다.

## 확인한 문제와 범위

실패 로그에는 오픈 추정 시각 T+38.2ms의 예약 요청과 사이트의 명시적인 이미 예약 완료 거절이 있었다. 캡차 실패나 DB 잠금 때문에 전송하지 못한 사례는 아니다. 서버 선예약인지 일반 경쟁 패배인지는 로그만으로 구별할 수 없다.

연결 예열은 coordinator가 수행하고 실제 전송 타이머는 별도 page worker가 계산한다. 예열 측정값을 worker가 받지 못해 기존 보정이 실제 실행에서 0으로 처리되었다. 일반 미오픈 Fast Path 및 페이지별 예약 흐름은 유지하고 이 전달 경로를 수정했다.

## 전송 시각 보정

- worker는 coordinator의 최신 측정 스냅샷을 읽는다. worker 생성 이후 예열에서 dict를 재할당해도 반영한다.
- 측정 시작으로부터 15초 이내, 성공 응답 또는 HEAD 405, 유한한 RTT 1~300ms만 적용한다.
- RTT/2는 실제 편도 시간이 아닌 추정치이다. 추정 보정은 최대 25ms, 최종 목표는 추정 오픈 시각보다 최소 5ms 뒤로 제한한다. 실제 서버 시각 오차나 경쟁 예약 성공을 보장하는 의미는 아니다.
- 측정이 없거나 오래됐거나 실패한 경우 원래 안전 여유를 유지한다.
- 최종 적용 보정량, 추정 오픈 기준 목표, 측정 나이를 기록한다. 동일 값의 반복 로그는 제한하되 0에서 유효 보정으로 바뀌는 경우는 즉시 남긴다.
- 실패 사례의 예열 44.9ms / 시각 정밀도 24.6ms를 사용한 로컬 계산: 보정 누락 시 T+29.6ms, 반영 시 T+7.15ms. 이는 목표 시각 계산의 변화이며 실전 요청 도착시간이나 승패를 재현한 수치가 아니다.

## 선택형 취소표 대기

- 고급 설정의 `취소표 대기 (1페이지 · 최대 10분 · 이번 실행만)`를 명시적으로 켠 실행에만 적용한다. 기본 OFF이며 설정에 저장하지 않는다. 실행 시작 또는 사이트/모드 변경 후 해제된다.
- 해당 실행만 1페이지를 사용하며 일반 모드의 기존 1~3페이지 슬라이더 값은 보존한다.
- 이미 오픈한 날짜에만 사용한다. 미래 오픈 또는 오픈 시각이 확인되지 않은 대상은 일반 모드를 사용하도록 안내하고 시작하지 않는다.
- 화면 준비 후 단 한 번 시작하는 최대 600초의 monotonic deadline을 사용한다. 인증 갱신이나 화면 복구로 기간을 늘리지 않는다.
- 최대 초당 1회의 새로운 목표 날짜·지점·테마 시간표 조회를 사용한다. 정확한 시간의 `enable=Y`와 실제 ID가 확인된 응답만 제출 근거로 사용한다. 과거 Fast Path 후보와 기존 ready/capacity 캐시는 재사용하지 않는다.
- 네트워크/조회 오류에는 제한된 지수형 대기, 429/5xx에는 유효한 Retry-After를 반영한다. 403 접근 거절은 중단한다. 대기는 최대 100ms 단위로 중지를 확인하지만 이미 전송된 HTTP의 기존 5초 timeout이나 OS 정지까지 즉시 종료를 보장하지는 않는다.
- 취소표 모드의 최종 제출 동작은 한 번만 시도한다. 성공·매진·응답 불명확 이후 자동으로 재투입하지 않는다. 인증 준비가 늦어지면 실제 슬롯을 다시 조회한다.
- 기존 예약을 취소하거나 입금을 진행하는 기능은 아니다. 사용자가 취소하면 반드시 다시 예약된다고 보장하지 않는다.

## 결과와 로그

과거 시간표에서 고른 제출 후보와 당일 실조회로 확인된 슬롯을 구분한다. 내부 후보 ID나 HTTP 200만으로 예약 성공을 확정하지 않는 기존 완료 응답/화면/예약번호 확인 흐름을 유지한다.

최종 버튼 동작이 예외로 끝나더라도 요청 전송이 관측됐다면 결과 불명확으로 멈추며, 같은 주문을 자동 재전송하지 않는다.

## 검증 한계

네트워크 응답·브라우저·시각을 대체한 회귀 검증과 실제 UI 표준 payload 전달 경로를 검증한다. 실제 사이트 예약·취소·결제나 부하 테스트는 하지 않는다. 최종 테스트 수, 소스 커밋, EXE와 공개 업데이트 검증은 릴리스 결과에 기록한다.
