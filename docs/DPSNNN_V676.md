# 단편선 v6.76 적용 안내

## 동작 변경

- 기존 HTTP 감시와 함께, 미리 연결한 비회원 브라우저가 새 Shadow DOM 달력의
  실제 날짜 선택 및 예약 가능 카드를 확인한다. 다른 날짜의 상품 ID를 조합하지 않는다.
- 날짜 버튼 활성화, 선택된 날짜, 표시된 날짜, 테마·시간, 예약 가능 표시,
  정상 카드 이동 후 URL의 날짜·상품 ID를 확인한다.
- Chrome 시작과 Playwright 연결을 예약 감시 시작 시 수행한다. 슬롯 발견 후에는
  준비된 연결에서 기존 HTTP 주문 세션의 쿠키로 결제를 진행한다.
- HTTP 감시는 같은 프로세스/호스트에서 최대 4개 동시 요청과 최소 50ms
  시작 간격을 공유한다. 상세 준비·주문은 감시보다 우선한다.
  429/5xx/연결 오류 감속과 Retry-After는 HTTP 감시·상세·주문에 공통 적용한다.
- 주문 전 원자적 기록을 남긴다. 응답 유실, 불명확 JSON, 프로세스 재시작 후에는
  같은 예약을 다시 생성하지 않는다. 명시적 서버 거절만 재시도한다.
- 완료 URL만으로 성공 처리하지 않는다. 결제 사전 확인 성공과 최종 접수 응답,
  올바른 완료 화면 및 조회용 예약번호를 함께 확인한다. 성공 표시는 입금 대기다.

## 최대 4건 동시 실행

기존 한 건 예약 화면도 그대로 사용할 수 있다. 여러 건을 한 프로세스에서
실행하려면 개인정보가 담긴 JSON 파일을 별도로 준비한다. 이 파일은 Git에 넣지 않는다.

```json
{"reservations":[
  {"branch":"gangnam","themePK":"행복","reservationDate":"2026-09-12",
   "reservationTime":"17:50","name":"예약자 이름","phone":"휴대전화번호","people":2}
]}
```

- 강남 테마: `행복`, `상자`. 성수 테마: `문장`, `자격`, `쥐`, `별`.
- 예약마다 이름·연락처·인원을 지정한다. 인원 생략 시 2인이다.
- 동일 슬롯 중복 등록은 거절한다. 4건은 서로 다른 상태와 브라우저를 사용한다.
- 일괄 실행은 건당 HTTP 감시 1개씩 사용하므로 총 4개다. 한 건이 끝나거나
  실패해도 다른 건은 계속 감시한다. 창에서 목록을 확인한 뒤 감시 시작을 누른다.

```powershell
& '.\dist\방탈출펭크로6.76_yescaptcha.exe' --dpsnnn-plan 'C:\private\dpsnnn-plan.json'
```

소스 적용 후 빌드 전 실행도 가능하다(기존 개발용 Python과 의존성이 필요하다).

```powershell
.\.codex-python-extract\SourceDir\python.exe app.py --dpsnnn-plan 'C:\private\dpsnnn-plan.json'
```

## 시작 전 확인

- 2026-09-12 예약 오픈 예정은 2026-09-06 00:00 한국시간이다. 감시는 미리 시작한다.
- 각 예약의 `비회원 결제 브라우저 연결 완료` 로그를 확인한다. 기존 작업이 Chrome
  슬롯 4개를 사용 중이면 확보되지 않는다. 해당 기존 예약의 상태를 먼저 확인한다.
- 강남은 확인 알림톡 수신 후 **30분 이내**, 성수는 **1시간 이내** 입금 안내다.
  실제 알림톡의 금액·기한을 따르고 예약자명과 입금자명을 맞춘다.
- 개발자 모드는 주문 전 멈추므로 실예약 모드와 구분한다. 일괄 창은 실예약 모드다.
- 중지 요청은 이미 서버로 전송된 예약을 취소하지 않는다. 접수 화면은 확인할 때까지
  프로그램을 켜둔다. 조회용 예약번호와 알림톡을 확인한다.

## 응답 불명확 시

`%LOCALAPPDATA%\Pengucro\dpsnnn-orders`에 로컬 중복방지 기록이 남는다.
기록은 원문 이름·전화번호를 저장하지 않으며 내부 주문 코드가 포함될 수 있다.
기존 기록이 있으면 자동 재주문을 막는다. 알림톡·기존 결제 화면·예약 조회로
실제 접수 여부를 확인해야 한다. 확인 없이 기록을 삭제하거나 새 주문을 만들지 않는다.

## 검증 경계와 Windows 릴리스

- 네 목표 시간의 미게시→게시 전환, 동일 시간 혼재, 주문 응답 유실, 날짜 불일치,
  재진입 및 재시작, 결제 사전 확인 실패를 모의 검증한다.
- 새 달력의 실제 선택자와 날짜 비활성 상태는 공개 사이트에서 읽기만 확인했다.
  실제 자정 전환·최종 주문·알림톡 발송은 이번 개발 환경에서 실행하지 않았다.
- 새 MFE API의 원본 요청/응답은 확보하지 못했으므로 그 스키마를 추측한 직접 요청은
  추가하지 않았다. 정상 달력 경로를 보조 감시에 사용한다.
- 실제 선점 시간 단축 수치는 아직 측정하지 않았다. 준비 시점 이동을 검증한 상태다.
- Windows EXE는 Windows에서 커밋된 소스로 빌드하고 `docs/AUTO_UPDATE_RELEASE.md`의
  전체 테스트·GUI·EXE smoke·서명 및 배포 검증을 완료해야 한다. Linux 결과로
  Windows 빌드 성공이나 실예약 성공을 대신 판정하지 않는다.
